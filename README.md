# Кабинет репетитора

Веб-приложение для частного преподавателя (настроено под подготовку к **ЕГЭ по информатике**): ученики, расписание, пройденные темы, оплаты и абонементы, контроль знаний, домашние задания, отчёты для родителей и личный кабинет ученика/родителя.

**Стек:** Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS, база данных и вход по e-mail — Supabase.
Mobile-first, светлая и тёмная тема, весь интерфейс на русском (₽, ДД.ММ.ГГГГ, неделя с понедельника).

## Два режима работы

| Режим | Когда | Где данные |
|---|---|---|
| **Демо** | переменные Supabase не заданы | в браузере (localStorage), сразу заполнено демо-данными |
| **Supabase** | заданы `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` | в облачной базе, вход по e-mail, доступ с любых устройств, кабинеты учеников |

Код и экраны одинаковые, отличается только слой хранения (`src/lib/backend.ts`).

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000 — в демо-режиме сразу откроется кабинет с 5 учениками и данными за 2 месяца.

Продакшен-сборка: `npm run build && npm start`.

### Публикация на GitHub Pages

Сайт собирается как статический (`output: "export"`). Workflow `.github/workflows/deploy.yml` собирает и публикует его при каждом push в `main`. Адрес — `https://<пользователь>.github.io/<репозиторий>/`.

Без секретов сайт работает в демо-режиме: у каждого посетителя свои данные в его браузере. Чтобы на Pages работал вход и общая база, добавьте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` в **Settings → Secrets and variables → Actions**. Затем укажите адрес сайта в Supabase (*Site URL / Redirect URLs*) и перезапустите workflow.

### Подключение Supabase (вход по e-mail, несколько устройств, кабинеты учеников)

1. Создайте проект на https://supabase.com (бесплатного тарифа достаточно).
2. **SQL Editor → New query** → вставьте содержимое `supabase/schema.sql` → **Run**. Скрипт создаст таблицы, политики доступа (RLS) и хранилище файлов `files`.
3. **Project Settings → API**: скопируйте *Project URL* и *anon public key*.
4. Создайте файл `.env.local` (образец — `.env.example`):
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
   ```
5. **Authentication → URL Configuration**: в *Site URL* укажите адрес приложения (локально `http://localhost:3000`).
6. Оставьте включённым **Authentication → Providers → Email → Confirm email**. Это важно: доступ ученика определяется по e-mail, и подтверждение не даёт зарегистрироваться под чужим адресом.
7. Перезапустите `npm run dev`, зарегистрируйтесь. Первый вход создаёт пустой кабинет. Демо-данные можно загрузить в **Настройки → Данные**.

Деплой: например, на Vercel. Импортируйте репозиторий, задайте те же две переменные окружения и добавьте адрес сайта в Supabase (*Site URL / Redirect URLs*).

### Личный кабинет ученика/родителя

В карточке ученика заполните поле **«E-mail для личного кабинета»** (можно несколько адресов через запятую, например ученика и родителя). Человек регистрируется или входит по ссылке с этим адресом и видит только своё: расписание, прогресс по темам, оценки, ДЗ и баланс. Изменять ничего не может. Личные заметки репетитора, тесты и материалы ему недоступны: это обеспечивают политики RLS в базе, а не только интерфейс.

В демо-режиме кабинет можно посмотреть кнопкой **«Глазами ученика»** в карточке ученика.

## Структура данных

```
settings (1 на репетитора: цены, правила отмены, пороги, шкалы перевода баллов)
subjects ─< courses (шаблоны программ) ─< topics (раздел + тема, порядок)
students ─< student_courses >─ courses           назначенные программы
         ─< student_topics  >─ topics            статус темы у ученика
         ─< lesson_series                         регулярные занятия (день недели + время)
         ─< lessons (topic_ids[], отчёт, оценка, статус, late_cancel)
         ─< subscriptions (N занятий, цена, срок)
         ─< payments (сумма, способ, за что → subscription)
         ─< assessments (баллы, темы, % по темам, шкала, ответы теста) >─ quizzes
         ─< homework (срок, вложения, статус, оценка) >─ lessons
         ─< notes
materials (файлы/ссылки) — topic_ids[]
```

**Баланс** не хранится, а вычисляется (`src/lib/logic.ts → ledger`): *сумма оплат − списания*. Списываются проведённые занятия, поздние отмены учеником (позже, чем за N часов, по настройке) и пропуски без предупреждения (по настройке). Если на дату занятия действует абонемент с остатком, списывается цена занятия по абонементу и уменьшается остаток. Поэтому любая правка задним числом сразу корректно пересчитывает баланс.

## Экраны

| Раздел | Что есть |
|---|---|
| Главная | занятия сегодня (кнопка «Провести»), неотмеченные прошедшие, неделя, ДЗ на проверку и просроченные, долги и последний урок абонемента, доход месяца против прошлого, ожидаемый доход, ученики без проверки более 14 дней |
| Ученики | поиск, фильтры (класс, статус, долг), карточка с контактами (звонок, Telegram, WhatsApp) и вкладками «Занятия», «Темы», «Оценки», «Домашние задания», «Оплаты», «Заметки» |
| Расписание | день, неделя (сетка на компьютере, список на телефоне), месяц; регулярные занятия; предупреждение о пересечениях; удаление одного занятия или всей серии |
| Программа | шаблоны программ, разделы, темы (порядок, копирование шаблона), матрица «ученики × темы» с цветами и % |
| Контроль знаний | результаты с фильтрами, конструктор тестов (один или несколько вариантов, открытый ответ), прохождение с автопроверкой и ручной правкой, пробники с переводом баллов, слабые темы (ниже 70 %) |
| Домашние задания | список «требуют действий», быстрые статусы, проверка с оценкой, файлы и ссылки, статистика выполнения |
| Финансы | балансы, текст напоминания об оплате, внесение оплаты и абонемента, оплаты за период, доход по месяцам, по ученикам, ожидаемый доход, экспорт CSV для Excel |
| Отчёты родителям | период, посещаемость, темы, проверки, ДЗ, редактируемые рекомендации, баланс; текст для мессенджера, печать или PDF |
| Материалы | библиотека файлов и ссылок с привязкой к темам |
| Настройки | цена и длительность по умолчанию, правила отмены, пороги, шкалы перевода баллов, предметы, тема оформления, экспорт и импорт JSON, демо-данные, очистка |

## Курс «ЕГЭ информатика»

Учебный план лежит в `src/lib/ege-informatics.ts`: 82 темы в порядке прохождения. Контрольные точки (обязательные и дополнительные симуляции, проверочные и контрольные работы) делят курс на 15 блоков, и каждый блок становится разделом программы, например «Блок 5 → Контрольная работа 2». Разборы симуляций и беседы — это занятия, а не темы, поэтому в программу они не входят.

- Добавить курс в свой кабинет (в том числе в режиме Supabase): **Программа → Шаблон «ЕГЭ информатика»**.
- Симуляции записываются как «Симуляция ЕГЭ» по шкале «ЕГЭ информатика» (29 первичных → 100 тестовых баллов).
- Проверочные и контрольные работы записываются с результатами по темам блока, поэтому сразу попадают в анализ слабых тем.

Шкала перевода баллов заполнена по последней известной мне таблице. Сверьте её с официальной на текущий год (Настройки → Шкалы).
